How to Use the Scanner

The CORS Exploit Scanner is designed to test APIs for Cross-Origin Resource Sharing (CORS) misconfigurations. Follow these steps to audit an endpoint:

1. Enter Target & HTTP Method

Paste the full URL of the API endpoint you want to test (e.g., https://api.example.com/v1/user). Select the HTTP method required by that endpoint (GET, POST, PUT, DELETE, OPTIONS, PATCH).

2. Select Scan Mode

Choose your desired testing capability:

  • Normal: Tests 11 fundamental CORS misconfigurations (wildcards, null origin, basic reflection). Fast and quiet.
  • ⚡ Aggressive: Tests all 56+ exploit vectors, covering domain spoofing, protocol abuse, encoding tricks, and header manipulation.
  • 👻 Stealth: Same as Aggressive, but uses randomized delays (300ms - 1000ms) between requests to evade Web Application Firewalls (WAFs).

3. Configure Authentication (Crucial)

CORS vulnerabilities are often only dangerous if the endpoint returns sensitive data. To test authenticated endpoints:

  • Credentials Toggle: Enable this if the target uses browser-based Session Cookies. The scanner will attach the cookies active in your current browser session.
  • Cookie / Bearer Token Input: Manually paste a grabbed session cookie or JWT token if you are testing an external target.

4. Review Findings & Generate Exploits

After clicking EXPLOIT SCAN, the 3-panel dashboard will populate. You can drag the vertical borders between the panels to resize them.

If a vulnerability is found, check the Risk & Exploits panel. The tool automatically writes ready-to-use Proof-of-Concept (PoC) code in HTML, Fetch JS, XHR, cURL, and Python that you can instantly copy and execute to verify the exploit.

How the Tool Finds Vulnerabilities

The core mechanic of CORS (Cross-Origin Resource Sharing) relies on the server inspecting the Origin HTTP header sent by the browser, and in return, deciding whether to append the Access-Control-Allow-Origin (ACAO) and Access-Control-Allow-Credentials (ACAC) headers.

If a server simply reflects whatever is in the Origin header back into the ACAO header, it essentially bypasses the Same-Origin Policy (SOP).

Detection Methodology

Our scanner automates the process of "fuzzing" the Origin header to trick the target server's validation logic.

1

Payload Injection

The scanner takes the target's URL and strips it down to its base domain. It then dynamically generates 56+ malicious origin payloads. For example, if the target is api.target.com, it will generate payloads like https://api.target.com.evil.com (suffix bypass), https://api.target.com%00.evil.com (null byte injection), or http://api.target.com (HTTP downgrade).

2

Cross-Origin Execution

The tool issues asynchronous HTTP requests from your browser context to the target, attaching these crafted Origin headers. It monitors the HTTP response status, body, and specifically the CORS security headers.

3

Classification & Validation

A vulnerability is only confirmed if the server responds gracefully (e.g., HTTP 200 OK) AND the Access-Control-Allow-Origin header matches our malicious injected origin.

HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://api.target.com.evil.com
Access-Control-Allow-Credentials: true

If Allow-Credentials: true is present alongside an attacker-controlled origin, the vulnerability is flagged as CRITICAL, meaning an attacker can steal authenticated session data on behalf of a victim.
